## API contract

Protected operations require the approved account's Supabase session access token:

```text
POST /analyze
GET /analyses/:id
GET /analyses?limit=100&offset=0
GET /intelligence-options
```

`GET /health` is public. History is scoped to the authenticated owner. Database access is through service-only RPCs, with RLS enabled and browser table access revoked.

Example request (no credentials):

```json
{
  "skill": "competitor_spy",
  "query": "Nike",
  "compare_with": "Adidas",
  "period_days": 90,
  "max_videos": 40,
  "intelligence_provider": "openai"
}
```

Trend Detector uses `skill: "trend_detector"` and `compare_with: null`. Providers are `openai`, `claude`, or `lovable`. Unknown fields are rejected. The sample budget is at most 50 videos total across both competitors. Time ranges are 1–365 days.

Both skills return `analysis_id`, `skill`, `status`, `kpis`, `charts`, `insights`, `videos`, `report`, `limitations`, and `generated_at`.

- Missing metrics remain `null`, not invented zeroes.
- Metrics and theme frequencies are calculated in code.
- Insights must reference retrieved internal video UUIDs.
- Publication charts do not prove historical engagement growth.
- Canonical videos are deduplicated; saved analyses retain immutable evidence snapshots.
- Errors use `{ error: { code, message, request_id } }`. Show useful backend messages to the user.
- Provider `configured` flags indicate configuration presence, not credits, model access, or a healthy live connection.

## UI integration already implemented locally

- `frontend/src/services/feedintelApi.ts`: central service; demo mode requires explicit `VITE_FEEDINTEL_MODE=demo`. Live failures never fall back to fictional data.
- `frontend/src/services/httpFeedintelApi.ts`: attaches the session bearer token, applies timeouts, preserves backend errors, and calls the correct endpoints.
- `frontend/src/services/backendContract.ts`: validates responses and maps the existing UI types to the backend contract.
- Provider translation: `openai_api` → `openai`, `anthropic_api` → `claude`, `lovable_ai` → `lovable`. Do not send UI-only `ai_provider` or `model_id` to the strict backend.
- History uses the backend's summary envelope rather than expecting full result objects. Unavailable summary video counts display as unavailable instead of fabricated values.
- `frontend/src/services/auth.ts` and `AuthGate.tsx`: browser-only Supabase client, password sign-in, session restore, sign-out, and cache clearing when users change. There is no signup UI.
- Provider choices respect configuration availability; preferences are saved locally and reused by skill forms. Settings labels distinguish configuration from connection health.
- Existing report, evidence, chart, mobile navigation, and print/PDF layouts are retained. Charts have animation disabled so print/screenshot output can render immediately.
- Only public client configuration was copied into `frontend/.env.local`; server secrets remain separate.
- Root convenience scripts were added for running, testing, and building the UI.
